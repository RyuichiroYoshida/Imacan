# ProjectImacan

## 在席・活動ステータス共有サービス 要件定義書（MVP）v1

## 1. 概要

### 1.1 背景

学校内で「今行けば誰かいるか」「自習仲間がいるか」を把握する手段が存在しない。

### 1.2 目的

ユーザーが以下の意思決定を行えるようにする：

- 学校に行くかどうか
- 自習するかどうか
- 誰かと合流するかどうか

---

## 2. スコープ

### 2.1 対象（MVP）

- 在席状態の共有
- 活動ステータス（授業中 / 自習中）の共有
- Discordログインによるユーザー識別
- PWAとしての提供

---

### 2.2 非対象（MVP外）

- リアルタイム位置追跡
- 地図表示
- バックグラウンド位置取得
- 詳細プロフィール
- 通知機能

---

## 3. 用語定義

| 用語 | 説明 |
|------|------|
| 在席 | 学校にいる状態 |
| 活動ステータス | 授業中 / 自習中 |
| Presence | ユーザーの状態情報 |
| TTL | 状態の有効期限 |

---

## 4. ユーザーストーリー

### 4.1 基本

- ユーザーとして、今学校に何人いるかを知りたい
- ユーザーとして、自分の状態を簡単に共有したい
- ユーザーとして、放置した状態が残り続けないようにしたい

---

### 4.2 自習ユーザー

- 朝から夜まで自習する場合、ステータスが途中で消えないようにしたい
- ただし帰宅後は自動的に消えてほしい

---

### 4.3 授業ユーザー

- 授業中のステータスは授業終了後に自動で解除されてほしい

---

## 5. 機能要件

### 5.1 認証

- :contentReference[oaicite:0]{index=0} OAuth2ログイン
- バックエンドでJWT発行

---

### 5.2 在席判定

- MVPでは位置情報を使わず、ユーザーの手動更新で在席と判定する
- 位置情報による学校半径内判定はMVP外の候補とする
- 位置情報を導入する場合も、正確な位置情報は保存しない

---

### 5.3 活動ステータス

| ステータス | 説明 |
|------------|------|
| CLASS      | 授業中 |
| SELF_STUDY | 自習中 |
| OUT | 退出 |

- 1タップで更新可能

---

### 5.4 状態表示

- 在席人数
- 活動別人数

#### 表示例

在席：5人
授業中：3人 / 自習中：2人

---

### 5.5 ステータス更新

- 手動更新（UI操作）
- 「帰宅」操作で即時退出

---

## 6. TTL（有効期限）設計

### 6.1 前提

- 学校開放時間：**9:00〜20:30**

---

### 6.2 ステータス別TTL

| ステータス | TTL | 備考 |
|------------|------|------|
| CLASS | 90〜120分 | 授業時間相当 |
| SELF_STUDY | 当日20:30まで | 長時間利用対応 |
| OUT | 即時削除 | |

---

### 6.3 期限ロジック

- `SELF_STUDY` は当日閉館時刻まで有効
- `CLASS` は一定時間後に自動解除
- いずれも閉館時刻を超えない

---

### 6.4 UX補助

- ステータス設定時に有効期限を明示
- 再訪時に継続確認を表示

---

## 7. 非機能要件

### 7.1 パフォーマンス

- API応答：300ms以内

---

### 7.2 セキュリティ

- JWT認証必須
- HTTPS必須

---

### 7.3 プライバシー

- 正確な位置は保存しない（または丸める）
- 履歴は保持しない
- オプトイン方式

---

## 8. API設計（MVP）

### 8.1 認証

POST /auth/discord/callback

---

### 8.2 ステータス更新

POST /presence
Authorization: Bearer <JWT>

```json
{
  "activity": "SELF_STUDY"
}
```

### 8.3 状態取得

``` json
GET /presence/summary
{
  "total": 5,
  "class": 3,
  "self_study": 2
}
```

### 8.4 自分の状態取得

```json
GET /presence/me
Authorization: Bearer <JWT>
{
  "active": true,
  "activity": "SELF_STUDY",
  "updatedAt": "2026-04-26T09:30:00Z",
  "expiresAt": "2026-04-26T20:30:00Z"
}
```

状態がない、または期限切れの場合は `active: false` を返す。

## 9. データモデル

``` go
type Presence struct {
    UserID    string
    Activity  string
    UpdatedAt time.Time
    ExpiresAt time.Time
}
```

## 12. UI/UX要件

1タップで状態変更
状態は即時反映
MVPでは位置情報許可を要求しない
操作は最小限

## 13. KPI（MVP）

DAU（デイリー利用者数）
同時在席人数
ステータス更新回数

## 14. リスクと対策

リスク 対策
利用者が増えない 小規模コミュニティから開始
プライバシー懸念 MVPでは位置情報を扱わず、履歴なし
ステータス放置 TTL + 自動失効

## 15. MVP実装優先順位

Discordログイン
JWT発行
ステータス更新API
Redis保存（TTL付き）
集計API
PWA UI

## 16. まとめ

本サービスは以下を最小構成で実現する：

在席状態の共有
活動ステータスの共有
軽量な操作性
プライバシー配慮

MVPでは機能を絞り、利用されるかの検証を最優先とする。
